A. 与 1411_plan.md 的七项计划一一对应

每张卡片对应 Plan 的一个章节，并明确区分原有能力、本次完成和剩余工作。

1. 唯一失败用例：public_0020

目标商品已经被召回，但大约排在第 214 位。因此它不是召回失败，而是排序能力与信息不足共同造成的问题。

之前已有

Exact/BM25、可选 Dense、RRF，以及问完可用信息后对未展示商品进行轮换。完整基线为 199/200。

本次已实现

完成失败归因；提问规划会寻找更有区分度的信息；增加“信息已耗尽”状态，避免反复追问。

仍未实现

自然语言回答提取、按身份/风格/使用场景进行簇探索，以及在验证后适当降低热门度压制。

2. 用户意图：购买还是浏览

固定 evaluator 的表达容易识别；真实自然语言需要一个保守、可回退的识别方案。

之前已有

解析器能识别固定的 browsing 句式，但识别结果几乎不会影响后续流程。

本次已实现

混合分类器：规则优先；首轮表达不清楚时可选用 LLM；输出意图类型与置信度。

仍未实现

让不同意图真正影响检索、结果多样性和探索强度。目前主要只影响提问优先级。

3. 用户画像的蒸馏与使用

必须区分“用户在意哪些维度”和“用户具体偏好什么取值”。

之前已有

画像标签只以 0.15 的很小权重参与 lexical 排序。

本次已实现

material、fit 等标签会提高对应澄清问题的优先级。

仍未实现

蒸馏正向/负向偏好及置信度；只有明确的具体偏好才能进入 Query 与 Dense 检索。

4. 上下文与记忆管理

目前最多十轮，对上下文压力不大；以后 LLM 开始读取更多历史时，动态压缩才真正有价值。

之前已有

当前/已替换约束、覆盖项、拒绝项、上一轮结果和已展示结果。

本次已实现

意图、置信度、提问焦点、提问历史，以及“信息已耗尽”状态。

仍未实现

近期原始对话 + 结构化长期记忆 + 压缩历史，并确保否定和偏好覆盖不会丢失。

5. 失败感知与 Prompt 演进

Agent 看不到 ground truth，只能通过重复、停滞、冲突和用户不满意等可观测信号判断策略是否失效。

之前已有

检索诊断与远程 provider 回退，但系统并不知道“当前策略本身正在失败”。

本次已实现

只加入了基础的“信息已耗尽”信号，还不等于完整的失败感知。

仍未实现

停滞/冲突检测、有限且可控的恢复动作，以及带回归门槛的离线 Prompt 演进。

6. Ask Attribute 不能永远只问 other

自然语言问题应该足够具体，同时继续兼容 bare-minimum evaluator 的协议。

之前已有

每轮都输出 other。它在 public evaluator 上有效，但在真实对话里过于模糊。

本次已实现

规划器先选 focus/topics，再由模板生成具体问题；协议层暂时仍输出 other。

仍未实现

基于 evaluator 可回答性的结构化属性选择、LLM 自然表达，以及检查 message 与 ask_attribute 一致性的 validator。

7. Semantic Search 与动态权重

Dense 目前只带来很小的 MRR 增益。50:1:1 看起来差距很大，但这本身不足以证明应该提高 Dense 权重。

之前已有

Exact/分字段 BM25、两路 Dense、加权 RRF，以及采用保守融合方式的可选 reranker。

本次已实现

没有修改任何检索权重；完整基线指标保持不变。

仍未实现

根据精确匹配强度、意图和 query 抽象程度动态调权；用户画像的优先级必须低于当前明确意图。

C. 建议实施顺序

这里与 plan 文档最后的顺序保持一致。“部分完成”只代表基础已经落地，不代表剩余工作可以跳过。

1. 定位 public_0020已完成：确认是排序 + 信息不足
2. 提问 Policy基础已完成；还需回答提取与属性选择
3. 意图路由分类已完成；还需影响检索与多样性
4. 用户画像蒸馏区分在意维度与具体偏好取值
5. 动态检索融合按意图与 query 调整 lexical/dense/profile
6. 动态记忆LLM 对话历史变长后再加入
7. 失败恢复有限恢复动作，再做离线 Prompt 演进

每一步都必须经过回归门槛：Hit Rate@10、MRR、MTTC、分场景指标、API 成本、延迟，以及是否引入新的失败用例。
